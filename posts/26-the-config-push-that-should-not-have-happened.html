The Config Push That Should Not Have Happened

August 2026 - tags: automation, change-management

Someone adding new devices to an automation tool accidentally aimed a live configuration push at production, and production noticed immediately.

What Happened

Most of the network neighbors at one site flapped down and back up within about half an hour. The cause was a configuration automation tool being used to add new devices, except the push meant for the new devices went out to the live network instead.

The Fix

The push was rolled back and the credentials that had allowed it to reach production in the first place were removed, closing that particular door for next time.

Jargon, Decoded

Flapping is when a connection between two devices repeatedly drops and reconnects instead of settling into one stable state, like a light switch someone cannot stop flicking. Automation tools are meant to make changes safer and faster, right up until they make a mistake faster too.

Lessons Learned

Automation is only as safe as the boundary between test and everything, and that boundary needs to be a wall, not a suggestion. A five minute credential scoping review is a lot cheaper than a thirty minute companywide flap.
