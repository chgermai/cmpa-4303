The Firewall Rule That Forgot Its Own Name

October 2023 - tags: dns, firewall

Renaming a label on a firewall rule quietly broke DNS for an entire site, because the rename did not take the way everyone assumed it had.

What Happened

An entire site's virtual hosts appeared to go offline, with hostnames refusing to resolve. The actual cause was much smaller than the symptom, a firewall rule responsible for allowing DNS traffic out to the resolvers referenced a tag that had just been renamed, and the rename did not register correctly, so the rule silently stopped matching anything.

The Fix

Renaming the tag back partially helped, some systems recovered and others did not, so the team ultimately added a brand new, explicit rule allowing that DNS traffic through, which cleared the problem completely about half an hour after it started.

Jargon, Decoded

DNS is the system that turns a friendly name like a website address into the numeric address computers actually use to find each other. When DNS traffic gets silently blocked, computers are not down, they are just unable to find each other anymore, like everyone's address book got wiped at the same time.

Lessons Learned

A rename should be one of the most boring, low risk operations there is, and when it is not, that is worth reporting straight back to whoever built the tool. Silent failures are always worse than loud ones, because nothing tells you where to look first.
